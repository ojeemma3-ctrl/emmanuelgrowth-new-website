# GrowthOS Studio — Codex Constitution

## Purpose

This document defines how Codex should operate while building GrowthOS Studio.

Before making any architectural, engineering or implementation decision, Codex must read and follow this document.

This document takes priority over convenience. The mission is more important than writing code quickly.

---

# What is GrowthOS Studio?

GrowthOS Studio is **not** a software project.

GrowthOS Studio is a **Marketing Operating System** that helps businesses:

1. Attract more customers.
2. Convert attention into sales.
3. Retain customers through intelligent follow-up.
4. Build trust through reputation management.

Every feature, folder, component and engineering decision must support one or more of these four objectives.

If a proposed feature does not help attract, convert, retain or build trust, question whether it belongs in GrowthOS.

---

# Company Mission

We help businesses attract more customers through AI-powered content, convert attention into sales with smart digital experiences, and retain customers through intelligent follow-up and reputation management.

Every technical decision should support this mission.

# Engineering Principles

Always:

* inspect before editing
* explain before coding
* build reusable systems
* avoid technical debt
* keep architecture clean
* document important decisions
* preserve maintainability
* prefer simplicity over cleverness

Never:

* hardcode brands
* hardcode colours
* hardcode copy
* create unnecessary abstractions
* introduce complexity without clear business value
* drift into unrelated features

---

# Creative Philosophy

Story comes before technology.

Marketing comes before visuals.

AI creates assets.

GrowthOS creates stories.

Remotion assembles and polishes.

Technology exists to strengthen marketing—not replace it.

# Quality Standard

GrowthOS does not produce "AI videos."

GrowthOS produces **commercial-quality marketing films**.

Every deliverable should be capable of representing a premium brand.

Every project should demonstrate:

* strategic thinking
* emotional storytelling
* cinematic quality
* polished motion
* premium typography
* refined composition
* professional pacing
* consistent branding
* excellent user experience

If a result feels generic, rushed or obviously AI-generated, improve it before considering it complete.

---

# Production Rule

GrowthOS Studio is judged by what it ships, not by what it plans.

Every week should produce at least one client-visible asset.

Client-visible assets include:

* Commercial films
* Product advertisements
* Brand campaigns
* Websites
* Landing pages
* Educational content
* Portfolio pieces
* Sales material

Engineering exists only to improve the speed, quality and consistency of producing these assets.

If engineering work does not improve production or client outcomes, question whether it should be done now.
